# Laiškelis — Letters for Strangers

An anonymous-ish letter-sharing app for a Lithuanian audience. Users with a
nickname-only account write short letters that are handed out at random to
other users, or pin them to a spot on a map of Lithuania. Letters expire;
recipients can ask the author for a private chat.

The product spec lives in [`product-flow.md`](product-flow.md); the rules and
schema an implementation must honour live in [`CLAUDE.md`](CLAUDE.md); the
running log of *why* things are the way they are lives in
[`decisions.md`](decisions.md). Read those before changing behaviour — the
safety model depends on deliberate scope.

**App UI copy is Lithuanian. Code, comments, and docs stay English.**

## Stack

- **Expo SDK 54** / React Native 0.81 / React 19, Expo Router (file-based
  routing, typed routes, React Compiler enabled)
- **Supabase** — Postgres, auth, RLS, realtime (chat), Edge Functions, pg_cron
- **Expo push notifications** via an outbox table drained by an Edge Function
- **MapLibre GL in a WebView** (`lib/map-html.ts`) with OpenFreeMap vector
  tiles — no map API key, no GPS permission anywhere
- **react-native-svg** for the crayon drawing canvas (`lib/drawing.ts`)

Windows is the development machine, so iOS builds must go through EAS cloud.

## Setup

```bash
npm install
npx expo start
```

### Environment variables

| File | Tracked? | Contains |
| --- | --- | --- |
| `.env` | yes (public values only) | `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` |
| `.env.local` | no (gitignored) | `SUPABASE_ACCESS_TOKEN` (CLI auth), `SUPABASE_SERVICE_ROLE_KEY` (seed script only) |
| `.env.eas-simulator` | yes | overrides for cloud-simulator runs |

Only `EXPO_PUBLIC_*` values are bundled into the app. The service-role key is
never used by the client — it exists for the seed script and the Edge
Function's own runtime environment.

### Native builds

The app uses several config plugins, so Expo Go is not enough — use a
development build:

```bash
npx eas build --profile preview-apk --platform android   # installable APK
npx eas build --profile preview-sim --platform ios       # simulator build
```

`/ios` and `/android` are gitignored: this is a managed (CNG) project and the
native folders are generated by prebuild.

## Database

Migrations are numbered SQL files under `supabase/migrations/`, applied to the
linked project with the Supabase CLI:

```bash
export SUPABASE_ACCESS_TOKEN=$(grep SUPABASE_ACCESS_TOKEN .env.local | cut -d= -f2)
npx supabase migration list      # see what's applied
npx supabase db push             # apply new migrations
```

Notes for anyone writing a new migration:

- Use `gen_random_uuid()`, not `uuid_generate_v4()` — the latter isn't
  resolvable through the CLI's connection `search_path`.
- Migrations 001–007 were originally applied by hand in the SQL editor and
  reconciled once with `supabase migration repair`; 008 onward went through
  `db push` normally.
- Privacy-sensitive access control belongs in RLS policies and
  `SECURITY DEFINER` functions, not in client code.

### Edge Functions

```bash
npx supabase functions deploy send-push-notifications
```

Docker is not required — the CLI uploads the asset directly. The function
reads `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` from its own environment,
which Supabase injects.

### Scheduled jobs

Four pg_cron jobs run in production:

| Job | Schedule | Does |
| --- | --- | --- |
| `letters-lifecycle-sweep` | `*/10 * * * *` | `expire_due_letters()`, `release_stale_claims()`, `expire_due_map_letters()` |
| `push-notifications-dispatch` | `* * * * *` | `net.http_post` to the `send-push-notifications` function |
| `reminder-notifications-enqueue-hourly` | `0 6,13,16,19 * * *` | `enqueue_reminder_notifications()` |
| `reminder-notifications-enqueue-1230` | `30 9 * * *` | `enqueue_reminder_notifications()` |

Check their health with:

```sql
select jobname, schedule, active from cron.job;
select jobname, status, start_time from cron.job_run_details order by start_time desc limit 20;
```

Expiry is also run lazily on receive and on moderation-queue load, so it never
depends on cron alone.
